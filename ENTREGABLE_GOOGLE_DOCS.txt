1. ESTRUCTURA DEL PROYECTO
--------------------------------------------------------------------------------

Descripción del repositorio:
El proyecto consiste en una aplicación backend desarrollada en Node.js y Express 
para la gestión de adopciones de mascotas (AdopMe API). Está estructurada 
siguiendo el patrón de arquitectura en capas (Layered Architecture), 
separando responsabilidades entre controladores, servicios, repositorios, DAOs y 
rutas HTTP. Incluye documentación interactiva con Swagger/OpenAPI, tests 
funcionales totalmente aislados con mocks (Sinon/Supertest) y un entorno 
dockerizado con una imagen optimizada basada en Node Alpine.

Propósito de carpetas y archivos principales:

- src/app.js: Punto de entrada de la aplicación. Configura los middlewares de Express, Swagger UI para la documentación de la API y la conexión condicional a MongoDB.
- src/routes/: Contiene la definición de las rutas HTTP expuestas por la API. En particular, `adoption.router.js` maneja los endpoints de adopción (`GET /`, `GET /:aid`, `POST /:uid/:pid`).
- src/controllers/: Contiene la lógica de control de peticiones HTTP y respuestas de la API, delegando la lógica de negocio a los servicios.
- src/services/: Define e instancia los servicios principales inyectando los repositorios correspondientes.
- src/repository/: Implementa el patrón Repository (`GenericRepository`, `AdoptionRepository`, etc.) para abstraer el acceso a datos.
- src/dao/: Data Access Objects que interactúan directamente con los modelos Mongoose (`models/`).
- src/docs/: Especificaciones OpenAPI / Swagger en formato YAML para la documentación interactiva en `/api/docs`.
- test/adoption.test.js: Suite de pruebas funcionales para los endpoints del router `adoption.router.js`, utilizando Mocks y Stubs para aislar dependencias externas.
- Dockerfile: Archivo de instrucciones para la construcción de la imagen de Docker optimizada para producción.
- .dockerignore: Define los archivos y directorios omitidos durante el proceso de build de la imagen Docker.

import request from 'supertest';
import { expect } from 'chai';
import sinon from 'sinon';
import app from '../src/app.js';
import { adoptionsService, petsService, usersService } from '../src/services/index.js';

describe('Suite de Tests Funcionales - Router Adoptions (/api/adoptions)', () => {

    afterEach(() => {
        sinon.restore();
    });

    describe('GET /api/adoptions', () => {

        it('Debería retornar un status 200 y la lista completa de adopciones (Caso Exitoso)', async () => {
            const mockAdoptions = [
                { _id: '647fa8c9e46dbc5a20320199', owner: '647fa8c9e46dbc5a20320181', pet: '647fa8c9e46dbc5a20320182' },
                { _id: '647fa8c9e46dbc5a20320200', owner: '647fa8c9e46dbc5a20320183', pet: '647fa8c9e46dbc5a20320184' }
            ];

            sinon.stub(adoptionsService, 'getAll').resolves(mockAdoptions);

            const response = await request(app).get('/api/adoptions');

            expect(response.status).to.equal(200);
            expect(response.body).to.have.property('status', 'success');
            expect(response.body.payload).to.be.an('array');
            expect(response.body.payload).to.deep.equal(mockAdoptions);
        });

        it('Debería retornar status 200 y un array vacío cuando no existen adopciones registradas', async () => {
            sinon.stub(adoptionsService, 'getAll').resolves([]);

            const response = await request(app).get('/api/adoptions');

            expect(response.status).to.equal(200);
            expect(response.body).to.have.property('status', 'success');
            expect(response.body.payload).to.be.an('array').that.is.empty;
        });

        it('Debería manejar errores del servidor retornando status 500', async () => {
            sinon.stub(adoptionsService, 'getAll').rejects(new Error('Database connection failed'));

            const response = await request(app).get('/api/adoptions');

            expect(response.status).to.equal(500);
            expect(response.body).to.have.property('status', 'error');
            expect(response.body.error).to.equal('Database connection failed');
        });

    });

    describe('GET /api/adoptions/:aid', () => {

        it('Debería retornar status 200 y el objeto de adopción al enviar un ID válido existente', async () => {
            const mockAdoption = {
                _id: '647fa8c9e46dbc5a20320199',
                owner: '647fa8c9e46dbc5a20320181',
                pet: '647fa8c9e46dbc5a20320182'
            };

            sinon.stub(adoptionsService, 'getBy').resolves(mockAdoption);

            const response = await request(app).get('/api/adoptions/647fa8c9e46dbc5a20320199');

            expect(response.status).to.equal(200);
            expect(response.body).to.have.property('status', 'success');
            expect(response.body.payload).to.deep.equal(mockAdoption);
        });

        it('Debería retornar status 404 con error "Adoption not found" si el ID de adopción no existe', async () => {
            sinon.stub(adoptionsService, 'getBy').resolves(null);

            const response = await request(app).get('/api/adoptions/nonexistentid123');

            expect(response.status).to.equal(404);
            expect(response.body).to.have.property('status', 'error');
            expect(response.body.error).to.equal('Adoption not found');
        });

        it('Debería retornar status 500 ante un error interno en la búsqueda por ID', async () => {
            sinon.stub(adoptionsService, 'getBy').rejects(new Error('Internal lookup error'));

            const response = await request(app).get('/api/adoptions/errorId');

            expect(response.status).to.equal(500);
            expect(response.body).to.have.property('status', 'error');
        });

    });

    describe('POST /api/adoptions/:uid/:pid', () => {

        it('Debería realizar la adopción con éxito (status 200) cuando el usuario y la mascota existen y la mascota no está adoptada', async () => {
            const mockUser = {
                _id: '647fa8c9e46dbc5a20320181',
                first_name: 'Juan',
                last_name: 'Pérez',
                pets: []
            };

            const mockPet = {
                _id: '647fa8c9e46dbc5a20320182',
                name: 'Firma',
                specie: 'Dog',
                adopted: false
            };

            sinon.stub(usersService, 'getUserById').resolves(mockUser);
            sinon.stub(petsService, 'getBy').resolves(mockPet);
            sinon.stub(usersService, 'update').resolves(true);
            sinon.stub(petsService, 'update').resolves(true);
            sinon.stub(adoptionsService, 'create').resolves({ _id: '647fa8c9e46dbc5a20320199', owner: mockUser._id, pet: mockPet._id });

            const response = await request(app).post(`/api/adoptions/${mockUser._id}/${mockPet._id}`);

            expect(response.status).to.equal(200);
            expect(response.body).to.have.property('status', 'success');
            expect(response.body.message).to.equal('Pet adopted');
        });

        it('Debería retornar status 404 con "user Not found" si el usuario no existe', async () => {
            sinon.stub(usersService, 'getUserById').resolves(null);

            const response = await request(app).post('/api/adoptions/invalidUserId/647fa8c9e46dbc5a20320182');

            expect(response.status).to.equal(404);
            expect(response.body).to.have.property('status', 'error');
            expect(response.body.error).to.equal('user Not found');
        });

        it('Debería retornar status 404 con "Pet not found" si la mascota no existe', async () => {
            const mockUser = {
                _id: '647fa8c9e46dbc5a20320181',
                first_name: 'Juan',
                pets: []
            };

            sinon.stub(usersService, 'getUserById').resolves(mockUser);
            sinon.stub(petsService, 'getBy').resolves(null);

            const response = await request(app).post(`/api/adoptions/${mockUser._id}/invalidPetId`);

            expect(response.status).to.equal(404);
            expect(response.body).to.have.property('status', 'error');
            expect(response.body.error).to.equal('Pet not found');
        });

        it('Debería retornar status 400 con "Pet is already adopted" si la mascota ya fue adoptada', async () => {
            const mockUser = {
                _id: '647fa8c9e46dbc5a20320181',
                first_name: 'Juan',
                pets: []
            };

            const mockAdoptedPet = {
                _id: '647fa8c9e46dbc5a20320182',
                name: 'Firma',
                adopted: true
            };

            sinon.stub(usersService, 'getUserById').resolves(mockUser);
            sinon.stub(petsService, 'getBy').resolves(mockAdoptedPet);

            const response = await request(app).post(`/api/adoptions/${mockUser._id}/${mockAdoptedPet._id}`);

            expect(response.status).to.equal(400);
            expect(response.body).to.have.property('status', 'error');
            expect(response.body.error).to.equal('Pet is already adopted');
        });

        it('Debería retornar status 500 ante un fallo durante el proceso de actualización', async () => {
            const mockUser = { _id: 'user123', pets: [] };
            const mockPet = { _id: 'pet123', adopted: false };

            sinon.stub(usersService, 'getUserById').resolves(mockUser);
            sinon.stub(petsService, 'getBy').resolves(mockPet);
            sinon.stub(usersService, 'update').rejects(new Error('Failed to update user'));

            const response = await request(app).post('/api/adoptions/user123/pet123');

            expect(response.status).to.equal(500);
            expect(response.body).to.have.property('status', 'error');
        });

    });

});

Explicación de validación por grupo de tests:

1. Grupo GET /api/adoptions: Valida la obtención masiva de adopciones. Se comprueba que responda status HTTP 200 con el listado esperado, que maneje adecuadamente colecciones vacías (array vacío) y que ante fallos inesperados responda con status 500 y formato de error JSON adecuado.

2. Grupo GET /api/adoptions/:aid: Valida la consulta individual por ID. Se prueba la recuperación exitosa de un registro existente por su identificador único (status 200), el manejo adecuado de registros no existentes retornando un mensaje claro "Adoption not found" con status 404, y el manejo de excepciones internas con status 500.

3. Grupo POST /api/adoptions/:uid/:pid: Valida el proceso completo de adopción asociando usuario y mascota. Comprueba la creación exitosa asignando la propiedad de la mascota al usuario (status 200), la validación de usuario no encontrado (status 404 "user Not found"), la validación de mascota no encontrada (status 404 "Pet not found"), el rechazo de adopciones duplicadas si la mascota ya fue adoptada previamente (status 400 "Pet is already adopted") y la resiliencia ante errores de persistencia (status 500).

3. DOCKERIZACIÓN
--------------------------------------------------------------------------------

Contenido completo del Dockerfile:

FROM node:20-alpine AS base

WORKDIR /app

COPY package*.json ./

RUN npm ci --only=production && npm cache clean --force

COPY . .

USER node

EXPOSE 8080

ENV NODE_ENV=production
ENV PORT=8080

CMD ["node", "src/app.js"]

Explicación de las decisiones de optimización:

1. Selección de Imagen Base (`node:20-alpine`): Se utilizó una distribución basada en Alpine Linux para reducir drásticamente el peso de la imagen final (~170 MB vs ~1 GB de la imagen estándar de Node), minimizando la superficie de ataque de vulnerabilidades del SO.
2. Caché de capas mediante `COPY package*.json ./`: Se copian los manifiestos de dependencias en un paso previo a la copia de todo el código fuente. Esto permite que Docker reutilice la capa cacheada de `npm ci` cuando se modifica únicamente código de aplicación, reduciendo los tiempos de construcción en builds posteriores.
3. Instalación de dependencias de producción (`npm ci --only=production`): Se instalan exclusivamente las librerías necesarias para el funcionamiento en runtime, excluyendo paquetes de desarrollo como `mocha`, `chai` y `sinon`, lo que mantiene la imagen ligera y segura.
4. Limpieza de caché con `npm cache clean --force`: Elimina archivos temporales acumulados por npm tras la instalación.
5. Seguridad mediante usuario no root (`USER node`): Se establece el usuario `node` incorporado por defecto en la imagen de Node.js, evitando la ejecución del contenedor con privilegios administrativos (`root`).
6. Exclusión de archivos con `.dockerignore`: Se excluyen del contexto de build carpetas como `node_modules`, `.git`, pruebas unitarias (`test`), logs y archivos `.env` locales.
